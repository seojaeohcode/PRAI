# 역할 분배: Claude Code가 감독하고, Codex가 검토하고, 사람이 좋고 나쁨을 정합니다

PRAI는 하는 일이 다른 에이전트 둘이 만들었고, 그렇게 쓰도록 만들었습니다.
아래 분배는 프롬프트에 적은 부탁이 아닙니다. 도구에 들어 있습니다.
설정은 `agents.json`에 있고, `prai review`가 샌드박스·모델·작업별 추론 강도·회차 상한을 지킵니다.
결정은 모두 ledger에 남습니다.

## 누가 무엇을 하나

| 일 | Claude Code (감독) | Codex (검토자) | 사람 |
|---|---|---|---|
| 콘티, `prai.json`, 캡처 계획 | 씁니다 | 검토합니다 (`storyboard`) | 목표를 줍니다 |
| 인트로·아웃트로 박자표 | 씁니다 | 검토합니다 (`beats`, 추론 강도 **xhigh**) | — |
| 렌더, 검사, 프레임 묶음 | 실행합니다 | 정지 화면을 검토합니다 (`frames`) | — |
| 새 코드(블록, CLI) | 씁니다 | 검토합니다 (`code`) | — |
| 레퍼런스 | 모으고, 보고, 관찰을 적습니다 | 후보를 찾고(`refs research`) 선택을 평가합니다(`refs`) | 좋아하는 영상을 줍니다 |
| 지적에 대한 결정 | **정하고** 이유를 적습니다 | — | 뒤집을 수 있습니다 |
| 최종 승인 | — | — | **소리를 켜고 보고** 공개합니다 |

## 실제 작업에서 나온 규칙

규칙마다 실제로 문제가 생긴 뒤에 만들었습니다.

1. **Codex는 검토만 합니다.** `-s read-only`로 실행합니다. 파일을 고치지 않고, 최종 결정을 하지 않습니다.
   합성 데이터, 에셋, 블록처럼 만들 수 있는 것은 감독이 직접 만듭니다. *(만드는 일을 둘로 나눴더니 더 느려지고 흐름을 따라가기 어려웠습니다.)*
2. **모델은 하나로 고정합니다.** 검토 모델은 `agents.json`의 `reviewer.model`에 적습니다.
   실행이 실패하면(사용량 한도, 요금제, 로그인) PRAI가 멈추고 원인을 알립니다. 다른 모델로 혼자 바꾸지 않습니다.
   다른 모델로 돌린 회차는 다시 합니다. *(약속과 다른 모델의 검토는 믿을 수 없어서 일을 다시 해야 했습니다.)*
3. **작업마다 추론 강도를 정합니다.** 설계 결정, 박자표, QA 판정, 마지막 회차는 `xhigh`입니다.
   콘티, 프레임, 코드, 레퍼런스 같은 일상 검토는 `high`입니다. `agents.json → reviewer.effort`에서 바꾸거나 한 번만 `--effort`로 바꿉니다.
   마지막으로 허용된 회차는 자동으로 `final`(xhigh)을 씁니다.
4. **회차에 상한을 둡니다(기본 4회).** 미리 계획합니다: ① 콘티 ② 박자표·레퍼런스 ③ 렌더 후 프레임(엔진을 바꿨으면 코드도) ④ 최종 회귀.
   마지막 회차에서 나온 것은 부작용까지 모두 고치고 끝냅니다. 남은 것은 ledger의 "알려진 한계"로 적습니다.
   지적이 내 수정의 부작용 위주로 바뀌면 일찍 끝냅니다. *(한 번은 검증이 12회까지 갔고, 10~12회는 대부분 수정의 부작용이었습니다.)*
5. **지적마다 결정을 남깁니다.** 수용(accept), 부분 수용(partial), 기각(reject) 가운데 하나를 고르고, 이유와 확인 방법을 `reviews/ledger.md`에 적습니다.
   기각한 지적은 새 근거가 없으면 다시 올리지 않습니다. 검토는 명령이 아니라 입력입니다.
6. **오래 걸리는 실행은 한 번만 합니다.** 코드를 고정하고, 검사 코드와 로그 표본을 Codex에게 한 번에(`xhigh`) 보여 줍니다.
   그다음 한 번만 실행합니다. 결과에서는 진짜 결함만 고치고, 영향받는 경우만 다시 돌립니다.
7. **과장하지 않습니다.** 화면에 나오는 숫자는 사실이어야 하고 출처("시연 자료 기준")를 붙입니다.
   겹침은 "위험"이 아니라 "검토 필요"라고 씁니다. 애매하면 감독이 표현을 낮춥니다.
8. **검사는 승인이 아닙니다.** `prai check`는 음량, 박 정렬, 스펙 문제를 재고, 프레임 묶음은 배치를 보여 줍니다.
   둘 다 영상이 좋다는 증명은 아닙니다. 공개하기 전에 사람이 소리를 켜고 한 번 봅니다.
9. **정할 수 있는 것은 묻지 않습니다.** 감독은 "A로 할까요, B로 할까요?"나 "계속할까요?"를 묻지 않습니다.
   정하고, 하고, 무엇을 왜 골랐는지 보고합니다. 사람만 줄 수 있는 것(취향, 공개 승인, 계정)만 묻습니다.
10. **병렬로 일하고 내가 띄운 것만 정리합니다.** Codex가 검토하거나 렌더가 도는 동안 감독은 다음 일을 합니다.
    프로세스는 내가 띄운 것만 PID로 멈춥니다. 이름으로 한꺼번에 끄지 않습니다.

## 실제로 쓰는 법

```bash
npm run prai -- review myapp storyboard     # 1회차
npm run prai -- review myapp beats          # 2회차 (xhigh)
npm run prai -- render myapp && npm run prai -- review myapp frames   # 3회차
npm run prai -- review myapp code --focus "src/motion/blocks.tsx"    # 필요할 때, 1회차로 셉니다
```

`prai review`는 다음 순서로 일합니다.
1. `agents.json`을 읽습니다.
2. `prompts/<종류>.md` 템플릿에 계획, 스펙, ledger를 채워 프롬프트를 만듭니다. `frames`이면 프레임 묶음 이미지를 붙입니다.
3. `codex exec -m <모델> -c model_reasoning_effort=<강도> -s read-only …`를 실행합니다.
4. 답을 `reviews/NN-<종류>.md`로 저장하고, ledger에 새 회차를 엽니다.

Codex CLI가 없으면 프롬프트 파일만 만들어 다른 곳에 붙여 넣을 수 있게 합니다.
Codex 실행 파일이 PATH에 없으면 `PRAI_CODEX`에 경로를 적습니다.
실제 예시는 [Excalidraw 예제의 ledger](../../projects/excalidraw/reviews/ledger.md)에 있습니다.
1회차에서 엔진 버그(프레임 묶음의 모든 칸이 0프레임)를 잡았고, 2회차에서 스타일 패널과 내보내기 버튼 클로즈업을 요청받아 반영했습니다.
